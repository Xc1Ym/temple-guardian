# 第一关切换后暂停修复

2026-10-13，按用户反馈复现第一关结束后点击“下一关”，画面没有继续动画的问题。

原版第一关结算的“下一关”按钮会创建玩法确认窗口，并移除旧结算窗口。两个窗口使用相同的父容器和深度 1000。原生实现创建新窗口时已移除旧窗口；旧按钮回调再次执行 `removeMovieClip()`，却无条件删除该深度的对象，误把新窗口移出了场景。游戏因此保留暂停状态，玩法确认窗口不可见。浏览器复现时没有控制台错误，单纯检查脚本错误无法发现此问题。

现在重复移除已删除的实例会直接返回，且只在父容器对应深度仍指向该实例时删除该位置。原始脚本、关卡数值、玩法选择和回合制的准备过程不变。

新增回归使用实际敌人移动和第一关结算，不直接设置“过关”状态。桌面检查下一关按钮打开的玩法窗口实际存在于场景树，然后选择回合制、确认，开始第二关并检查敌人继续移动；手机路径检查原有继续按钮后的相同步骤。旧实现会在窗口存在性检查失败。

回合制进入新关后仍需要点击原版“开始 [SPACE]”或按空格；手机使用“开始 [空格]”。第一关桌面确认玩法后进入第二关准备阶段，这是原版流程。

验证：`npm test` 共 68 项通过，TypeScript／Vite 构建与素材检查通过。更新后的本机 Docker 生产预览实际完成第一关，在“下一关”后显示玩法确认窗口，选择回合制并确认后进入第二关；按空格后敌人出现、移动，控制台无错误。截图见 `qa-wave-two.jpg`。arm64 预览容器健康，更新后的 amd64 镜像也已构建并临时启动，健康接口返回 `ok`。
