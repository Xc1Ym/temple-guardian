# 研究加成传递修复

验证日期：2026-10-14。针对“升级研究后加成没有实际产生”的反馈，检查全部五项研究的鼠标操作、六个等级、三种玩法、已有／新建设施、升级、交易及实际弹丸伤害。

## 发现与修复

| 场景 | 修复前 | 修复后 |
| --- | --- | --- |
| 土木研究后新建弩箭塔 | 当前耐久为 65，上限仍为 50；原等级脚本只给 HP 乘倍率。 | 当前耐久及上限均为 65，设施升级后继续使用研究倍率。 |
| 神恩研究后新建或升级神御塔 | 神电坛／神火坛的等级脚本误读 `All_FanWei`，没有使用神恩的 `AllSen_FanWei`。例如一级神电坛仍是 95 射程。 | 使用神恩倍率，一阶神电坛在神恩一级时为 104.5 射程，范围圈同步变化。抛射不再错误地影响新建神御塔。 |
| 耐久制中的土木研究 | 最大耐久和当前耐久增加，但实际开火消耗的 `HPmini` 未增加；开火会把耐久写回旧数值。 | 增加与耐久上限差额对应的计数，保留已消耗的三分之一点余量；设施升级时同步计数。无关研究不会补满受损设施。 |
| 研究操作反馈 | 仅显示小的等级数字，很难判断具体加成。 | 原版提示栏显示研究名称、等级、作用对象和倍率／价格比例，不增加额外界面。 |

前两项及消耗计数问题来自原脚本本身：原始脚本、SWF 和 EXE 保持不变，本次在原生运行时中修正这些遗留问题。因此，研究场景的上述行为是有记录的修复，不声称与这些原作缺陷逐帧一致。

依据包括 [弩箭塔等级初始化](../reference/scripts/DefineSprite_451/frame_1/DoAction.as)、[神电坛等级初始化](../reference/scripts/DefineSprite_483/frame_1/DoAction.as)、[神火坛等级初始化](../reference/scripts/DefineSprite_506/frame_1/DoAction.as)、[开火时耐久消耗](../reference/scripts/DefineSprite_465/frame_5/DoAction.as) 和 [F_UpdateSeSi](../reference/scripts/frame_22/DoAction_4.as)。原静态生成脚本没有手工修改。

## 原版研究规则

| 研究 | 作用对象 | 每级效果 |
| --- | --- | --- |
| 锻造 | 弩箭塔、投石台 | 攻击倍率增加 0.4 |
| 抛射 | 弩箭塔、投石台 | 射程倍率增加 0.1 |
| 土木 | 防御／神御设施和陷阱 | 最大耐久倍率增加 0.3 |
| 神恩 | 神电坛、神火坛 | 射程倍率增加 0.1 |
| 神算 | 建造、升级和出售 | 建造／升级费用比例减少 0.05，出售价格比例增加 0.05 |

每项最多六级。研究价格、攻击命中时的倍率／取整、建造及交易的取整继续执行原脚本。土木作用于设施，不改变神殿自身的升级规则。

## 验证

`src/research.test.ts` 追加研究回归，覆盖上述失败场景、真实按钮命中、三种玩法下全部研究的六级费用和效果、原始字节码基准中的全部 26 个设施等级、实际建造／升级／出售交易、部分耐久消耗及实际弹丸命中。

在固定敌人位置、保留原开火／弹道／命中逻辑的对照中，锻造零、一、二级弩箭塔首次命中的实际伤害分别为 **12、24、40**。该数值保留原作在弹丸命中时再次使用攻击倍率的公式；测试同时检查实际敌人 HP，不能只提高面板数字通过。

修复前，新增回归分别复现新塔耐久上限 50、神御塔射程 95，以及耐久制计数没有随研究增加的问题。修复后，这些回归和原有未研究场景的字节码对照通过。中文仍需 591 个汉字，缺字为 0。

本地浏览器复核使用原版鼠标按钮：五项研究升到一级后，已有／新建弩箭塔均为 65/65 耐久，新建神电坛为 104.5 射程、260/260 耐久，运行错误为 0。证据见 [测试场景截图](qa-research-fix.jpg)。

可运行 `npm run dev`，在终端所示本机地址后加 `/tools/research-qa.html` 打开复核场景。该页面仅供开发，初始金钱及神迹设为 10000，以便快速检查全部研究；不加载浏览器存档，不进入生产构建。

完整设备及验证边界见 [verification.md](verification.md)。
