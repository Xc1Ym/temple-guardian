| 偏差 | 修复及依据 |

## 原始字节码对照

开发工具在 SWF 副本中追加启动及记录动作，运行保留的原字节码；正式构建不包含该副本或 Ruffle。参考环境为本地 Ruffle 0.7.1，使用字体 SWF 补齐宋体。

| 对照 | 覆盖和结果 |
| --- | --- |
| 设施等级 | 10 种设施的全部 26 个等级记录：价格、升级价格、金钱／神迹消耗、攻击、耐久、射程、速度、间隔及预览值一致。最高等级仍保留原脚本中残留的预览字段，不改变原版规则。 |
| 50 关生成 | 固定 `Math.random() = 0.5`，逐一比较全部 50 关的 560 个敌人记录：数量、种类、等级、生命、攻击、速度、奖励、护盾及隐身参数一致。 |
| 实战 | 地图 0、回合制、第一关、8 座弩箭塔，运行 840 个逻辑帧；243 个采样点逐项对照敌人位置、生命、死亡／显示状态、炮塔动画帧、弹丸位置／动画帧、神殿生命、金钱、剩余敌人和得分。除旋转浮点读值容差小于 10⁻⁷ 度，其余对照字段一致。最终金钱 485、得分 34、神殿 50。 |
| 形状碰撞 | 15 个普通敌人及 101／102／9999 三个特殊角色，在 0／45／90 度各采样 25×25 个点，共 33,750 点，全部一致。测试包含原始角色中隐藏的子图形。 |
| 运行时 | 原副本验证深度交换后的帧顺序、零缩放恢复、负缩放读值及坐标截断；保留自动过关、有效等级同帧跳转、滑块偏移和暂停倒计时的回归。 |

参考播放器在装饰随机交换 `_name` 时出现子对象查找偏差，不能用该异常画面判断道路还原。实战对照双方均将装饰留在原始坐标，仅在测试中禁用 `F_MapSuSiRan`；攻击、移动、建造、计分和出怪均执行原游戏函数。正式游戏继续执行装饰随机交换，另以 10 地图×3 随机种子×2 连续生成验证 169 格没有覆盖和重复坐标。此设置是控制实验条件，不是正式游戏改动。

自动回归共 **80 项通过**。同时通过 TypeScript／Vite 构建、素材来源与矢量碰撞数据检查；当前所需 591 个汉字缺字为 0。

生产浏览器实际操作确认：原版开始菜单、直接建造（80→71 金钱）、升级（1→2 级，71→46 金钱）、第一关自然结算后打开玩法确认窗口、第二关敌人沿道路移动，以及第二关结算两秒后自动进入第三关。提示、属性和结算中文正常，控制台无错误；`qa-logic-audit.jpg` 记录第三关准备界面。

最终 arm64 与 amd64 Docker 镜像均已构建并实际启动，UID 101、健康状态 `healthy`、8080 健康接口返回 `ok`。amd64 启动核查在无外部网络的临时容器中进行；两种镜像中的游戏数据校验值与本地 `dist` 一致。
