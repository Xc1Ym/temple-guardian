# 地图草地缺失修复

用户指出泥地显示成大片空地，无法看出唯一道路。原始地图数据没有岔路，问题出在原生运行时的地块引用语义。

原版 `F_MapSuSiRan` 会随机交换草地／障碍物的坐标、网格索引、深度和 `_name`。旧实现每次读取父对象的具名属性时，只按当前 `_name` 查找子对象；重命名后，后续访问就会错误地指向另一个地块，或读取到空对象。部分地块的 `Myix/Myiy` 因而被写成 undefined，坐标发生重叠，底层泥地露出。

修复保留 `attachMovie` 创建的父对象具名引用，显示名称变更不重新绑定该引用；移除地块时清理引用，重新创建同名实例时替换引用。原版随机顺序、障碍物数量、草地与道路数据均保留，没有重新设计地图。

新增十张地图的回归检查。每图使用三个固定随机种子，并连续生成两次，共 60 次地图生成；每次要求：

- 169 个网格坐标均存在且互不重复。
- 每个地块的类型与原版 13×13 数组一致。
- 显示坐标与网格索引一致。
- 重复开始不会保留过期具名引用，且没有脚本错误。

也检查了原 SWF 的 `F_MapSuSiRan` P-code，确认重命名的执行顺序。旧测试只校验地图数组是否合法，没有校验生成后地块覆盖，未能捕获该问题；现已补足。

2026-10-13 补充：固定随机值 0.5 的字节码探针中，Ruffle 0.7.1 也出现了装饰重命名后的查找偏差。不能以该异常画面代替原脚本和地图数据。实战差分仅在双方测试中固定装饰布局；正式游戏继续保留随机装饰，验证见 `logic-audit.md`。
